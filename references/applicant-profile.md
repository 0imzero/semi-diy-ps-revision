# Applicant profile workflow

Use this route once before tailoring individual programmes, and again only when the applicant adds or corrects material. The output is a reusable evidence base, not a PS draft.

## Locate the applicant root

The applicant root is the directory containing reusable folders such as `CV/`, `Personal_Materials/` and `Academic_Projects/`.

- If the current directory already contains those folders or `Applicant_Master_Profile.md`, treat it as the root.
- If the current directory is a programme folder, inspect its parent for the profile and reusable folders.
- If more than one plausible root exists, show the candidates and ask which one to use.
- Never create a second master profile inside a programme folder.

Read all applicant-provided files that affect factual evidence. DOCX, PDF, spreadsheet or plain-text materials may contain useful detail absent from the CV. The CV is an input and a consistency reference; this route does not rewrite it unless separately requested.

## Read and reconcile material

Build a source inventory and extract education, courses, awards, internships, academic projects, leadership, methods, tools, motivations, ability gaps and career direction. Preserve exact dates, role titles, team sizes, sample sizes and results when supported.

When sources disagree, do not silently choose the more impressive version. Record the conflict and ask a focused question if it would affect a PS, CV, recommendation or interview. User-confirmed corrections override older files.

## Deepen experiences with STAR plus reflection

For each material experience, organise the applicant's first-person account using:

- **Situation** — the real context, problem, constraint and why it mattered;
- **Task** — the responsibility or question assigned to the applicant;
- **Action** — the applicant's own steps, decisions, tools and methods;
- **Result** — the verified output, adoption, finding, feedback or outcome;
- **Reflection** — what the applicant understood differently afterward;
- **Remaining ability gap** — what the applicant can begin doing but still needs systematic postgraduate training to do well.

The Action section should preserve enough professional detail to show individual contribution. Prefer chronological stages, project stages or work types when they clarify the process.

Quantify only what is supported. Useful quantities include sample size, coverage, frequency, team size, time frame, number of outputs or documented adoption. Do not invent efficiency gains, accuracy improvements, revenue impact, rankings or praise.

## Ask only productive follow-up questions

Do not stop merely because some detail could be richer. First create the most complete profile supported by existing material, then list high-value questions under `Questions for Further Development`.

Prioritise questions that can unlock a concrete decision or difficulty, the applicant's exact contribution, a verifiable result, a genuine change in understanding, a programme-relevant ability gap, or a credible early-career direction. Avoid generic questionnaires whose answers would not change evidence selection or positioning.

## Output schema

Write or update `<Applicant_Root>/Applicant_Master_Profile.md` with:

```markdown

> Updated: YYYY-MM-DD
> Sources reviewed: ...

## Education
## Relevant Courses and Academic Preparation
## Methods, Tools and Technical Skills
## Internships and Professional Experience
## Academic and Course Projects
```

Preserve useful detail even when it is not suitable for the current PS; another programme may need it. Mark uncertain details without turning the profile into a bureaucracy of labels.

## Completion condition

This route is complete when the root profile contains the best currently available evidence, identifies material inconsistencies and supplies targeted next questions. It must not create a programme folder or draft PS prose.
